# Deferred V2 security interfaces

These names are review proposals. They are absent from `openapi.json` and Rails routes until the owner implementations and fleet security checks exist.

## Native session broker

Proposed operations: `beginNativeAuthorization`, `exchangeNativeAuthorization`, `getNativeSession`, `logoutNativeSession` under `/v2/native/auth/*`. `begin` binds a fixed native client ID, allowlisted HTTPS App Link or verified custom scheme, RFC 7636 S256 challenge, server-generated nonce and short expiry to one pending authorization record. `exchange` consumes the code once under the same client, redirect and verifier, and returns an opaque native session handle to the native host broker only. The React renderer receives scoped capability/status, never a refresh token or Auth signing material. Logout revokes that handle and current server session generation. An unrecognized platform, redirect, repeated callback, wrong verifier, expired state or identity switch must fail closed. No browser cookie is copied into a local Tauri origin. Orion/Astrid must supply target OS secure-store and callback evidence; Rails auth owner must select concrete challenge/exchange storage and CSRF/session semantics before activation.

## Synthetic inbound ingress

Proposed operation: `ingestFakeInboundEvent` at `POST /v2/test/inbound/fake`, admitted only by the isolated test profile. HTTP authentication derives actor, organization and mailbox capability from the current server session. The request may contain a bounded provider event key and plaintext MIME fixture; it cannot carry `authorized_mailbox_ids`, arbitrary organization context or live provider credentials. Corin's store must atomically persist `(organization, mailbox, provider, event_id)` before the response reports `created` or `duplicate`. A missing or revoked mailbox capability, malformed provenance, HTML payload, cross-tenant replay or disabled profile returns a deliberate error without persistence. No provider delivery or live SMTP follows from this operation. Corin/SQL owner must supply the durable store and scoped adapter before Cassian versions an active route.

## Personal display-name preference (PREF-822)

A separate noncanonical OpenAPI draft is at `proposals/personal-preferences.openapi.json`. GET/PUT `/v2/me/preferences` derive organization and user from the authenticated current session; neither operation accepts a user or organization ID. GET includes current `context_id` and `authorization_version` plus the bounded `display_name: string|null` (at most 256 Unicode code points) and nonnegative revision; PUT supplies `expected_revision` and CSRF proof and returns display name/revision. Missing/current-org or cross-user context returns a generic 404, and stale revision returns 409. This is a proposal only: no canonical V2 operation, Rails registration, generated DTO or fleet acceptance is claimed. Theo owns the isolated migration/service/controller implementation and will supply exact response/error evidence before activation.

## Inbox attachment read surface (ATT-823)

The noncanonical read draft at `proposals/inbox-attachments.openapi.json` proposes two message-bound GETs: a bounded five-field metadata page with UUID cursor pagination, and a clean-only byte stream. Both bind mailbox, thread, message and attachment identifiers to the current authenticated read scope; the byte response has `no-store`, `nosniff` and a sanitized attachment disposition, and never returns a storage key or public URL. Invalid input is 400, unavailable scope is 404, and an authorized but unclean object is 423. No browser upload, outbound draft/send attachment, scanner/verdict mutation or active route is proposed. Nadia's isolated service has `find` and `download` but no list, streaming Rails adapter, API-safe private Storage gateway or installed scanner; Corin's inbound staging handoff is pending. Until those dependencies and fleet RLS/HTTP/browser evidence exist, every byte request remains held.

## Inert campaign sequence draft (OUT-824/SEQ-831)

Root accepted the separate noncanonical shape at `proposals/outreach-sequence.openapi.json`: GET/PUT `/v2/outreach/campaigns/{campaign_id}/sequence` for one draft per campaign. PUT body matches Maeve's strict `DraftInput`; `campaign_id` must equal the path, null `expected_version` creates (201), an integer replaces (200), and an exact operation replay returns the prior result without mutation. GET returns current `id,campaign_id,version,status,timezone,steps`; absent/inaccessible is generic 404. Malformed input is 400; stale revision, operation mismatch and `reschedule_required` are deliberate 409 codes. `draft|held` is inert metadata, never send eligibility. No controller/read service, due claim, active route, generated canonical DTO or fleet proof exists yet. Celeste owns the editor; Maeve owns persistence; Dorian/SEC802 authority and Soren disposable SQL/HTTP are dependencies before activation.

The separate noncanonical `proposals/mailbox-assignee-options.openapi.json` defines a mailbox-scoped eligible Auth UUID picker page for a current assignment-capable actor. It returns only context/version, mailbox ID, current eligible user UUIDs and a signed opaque cursor, with no profile or proposed roster metadata. Sabine's protected SQL, Theo's controller and fleet authorization proof are prerequisites to canonical route activation; V1 assignment remains final authority.
