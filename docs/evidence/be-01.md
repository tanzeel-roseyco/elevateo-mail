## Checkpoint A observations (working tree, not yet a reviewed commit)

- Readiness: `GET /ready` -> `{"status":"ready","outbound_hold":true,"checks":{database,auth,storage,mail_catcher all true}}`; `/health` ok. Worker logs `worker.idle`, `dispatch: disabled`.
- Network: every runtime container attached only to `elevateo-local_runtime` (`internal=true`), no port bindings.
- A04 (`ops/tests/egress-check.sh`): control container reached the isolated fixture; api, worker, auth, mailpit, storage could not. Fixture network/containers removed by trap.
- Mailpit: `MessageRelay.Enabled=false`, `MP_SMTP_RELAY_ALL=false`, RDNS disabled, no webhook/forward settings.
- A02: non-allowlisted SMTP (`smtp.gmail.com`, `localhost`, `host.docker.internal`), missing `API_DB_PASSWORD`, `ELEVATEO_OUTBOUND_HOLD=false`, `INSTANTLY_API_KEY`, non-internal Auth URL, privileged `ELEVATEO_DB_ROLE`, malformed principal UUID: each raises a named error without echoing values.

- Idempotency: second bootstrap preserved secrets file hash; second migrate no-op.
- Stop/start: migration version in `app_meta.schema_migrations` retained; readiness restored.
- Defect found and fixed in-task: database.yml `schema_migrations_table_name` was ignored, so bookkeeping landed in `app`; moved to `config.active_record.*_table_name` and relocated the two disposable bookkeeping tables with `ALTER TABLE ... SET SCHEMA app_meta` (local dev DB only).
