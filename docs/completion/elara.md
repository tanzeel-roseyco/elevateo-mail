## Transport inventory and later activation seam

Current outbound class is `SendWorker::DurableLocalDriver`; it writes a private local receipt ledger and never emits SMTP or an API call. `LocalFailureDriver` is memory-only test scaffolding. `Config` requires the outbound hold and accepts only `mailpit:1025` as a configured SMTP endpoint, but no worker transport uses Mailpit. There is no selected production-capable outbound adapter, credential reference format, MIME renderer, or external acceptance lookup. Immutable review snapshot bytes are capped at 1 MiB; that cap is not a MIME output limit. Existing `SubmissionResult` normalizes local `accepted`/`rejected`/`unknown`, and exact-attempt observation reconciles a lost local response. No actual delivery, provider response, or real SMTP acceptance claim is made.

After integrated worker acceptance, a narrow self-hosted-compatible adapter can retain the same `submit(bytes, send_id:, attempt_id:, deadline:)` and `observation(send_id:, attempt_id:, snapshot_digest:)` boundary, with an explicit transport profile and separate credential reference resolved only inside the worker. Start with isolated Mailpit protocol tests and a bounded plain-text MIME renderer; any production-capable SMTP/API profile needs its own approved activation, credential handling, TLS/timeout policy and provider-specific receipt semantics. SMTP acceptance lost across a timeout has no safe generic status query, so that path must remain `unknown` for manual reconciliation and must never trigger blind retry. This is a proposed future scope, not implemented or authorized live transport.
