## Numbered defects

1. **MEDIUM — container security checks accept weaker settings than the claimed boundary.** `acceptance_cleanup.py:34-40` accepts any security option beginning with `no-new-privileges`, including a false setting, and accepts any non-unconfined `seccomp=` value instead of requiring the approved profile. Hashing the source profile at runtime lines 66-75 does not prove that the created container uses it. A changed Compose security setting can therefore pass this pre-start/pre-removal validator while weakening the advertised sandbox. Minimal repair: accept only Docker's actual enabled no-new-privileges representation and compare the inspected seccomp configuration with the recorded approved configuration, accounting explicitly for Docker's inspect representation. Add focused rejection cases for disabled privileges protection, a different permissive profile, and missing options; retain a known-good inspected fixture. This finding concerns the validator's demonstrated predicate, not a claim that the uninspected frozen Compose currently requests unsafe settings.

2. **MEDIUM — case count permits duplicate evidence to substitute for missing scenarios.** `acceptance_runtime.py:232-239` counts filenames and validates each record's schema/status/run/dispatch/lane/profile, but never establishes unique scenario identities or compares them to the selected lane's expected identities. Four copies of one valid passed case under distinct filenames satisfy the four-case predicate; the equivalent substitution works for the 26-case lane. This can produce lane `PASSED` without the stated authored case set. Minimal repair: compare a unique set of schema-defined case identities against the explicit expected identities for that lane, failing duplicate, missing, and unexpected identities. Add Docker-owned regressions for a valid set, duplicate replacement with unchanged file count, and missing/unexpected records. This remains a selected-lane gate, not certification of T4's full matrix; the external schema and producer were not inspected or assumed to guarantee directory-wide uniqueness.
