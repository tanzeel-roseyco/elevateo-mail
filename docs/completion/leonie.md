## Release and rollback template

Before release, collect: immutable source SHA and review ledger; artifact SHA256 plus provenance and SBOM for each deployable image/client; pinned image digests and redacted configuration diff; signing identity and verification receipt; full Soren test and restoration receipts; failed-test/blocker disposition; encrypted off-host retention and recovery objective approval; capacity and monitoring receipts; explicit root approval. Keep secret values and backup contents in the restricted vault only. Freeze sends/outbound control, pause workers and writers, take a verified paired backup, deploy signed pinned artifacts, run migrations and privileged/RLS checks, then perform a controlled synthetic smoke. Root decides activation.

Rollback: hold outbound dispatch and pause workers first; preserve provider acceptance history and external control epoch outside the restored DB; identify exact signed previous artifact and compatible schema. Prefer application artifact rollback where schema remains compatible. If database restore is required, restore only to a fresh isolated target, compare manifests and ledger, reconcile accepted/uncertain sends without resubmission, then switch under root approval. Never restore over persistent test/live data or reset an epoch to reenable old intents. Failed verification keeps dispatch held and release blocked.

Live provider sends, production dump/restore, Hetzner/DNS, native Windows/macOS install/signing, public TLS, capacity/RPO/RTO and actual approval are **open**. This packet is simulation/planning evidence, not an activation claim.

Design tradeoff for root: a checksum validator is small and auditable, but hashes establish byte integrity only, not backup consistency or off-host recoverability. The existing marker restore gives a fast local recovery signal; migration reversibility and role/RLS checks require actual restored application schema and dedicated fixtures. A production rehearsal adds fidelity but requires explicit live data handling and authorization, so this packet stops at task-owned test data.
