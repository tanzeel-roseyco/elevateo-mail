## V2 continuation (2026-10-15)

Added owned controllers under `apps/server/app/controllers/v2/outreach/` for campaign, lead and account list/detail/create/update and campaign analytics. `record_consent`, `withdraw_consent` and `suppress` are separate lead actions. All actions inherit protected session context, CSRF/origin checks, current authorization, tenant transaction and bounded JSON handling from the existing V1 boundary. Cassian owns route activation and canonical v2 DTOs; Celeste owns the client pages. A newly created lead is always `unknown`; a separate attested consent action supplies source/time, with server actor identity captured in persistence. This record does not authorize a send.

Migration 00009 continuation adds per-record optimistic versions and an operation ledger. Updates serialize identical operation keys inside the tenant transaction and return the stored result for exact retries; stale versions and changed payloads fail. Account RLS also checks current mailbox visibility. Lists use ID keyset pagination with a maximum of 100. Analytics counts persisted leads and currently consented unsuppressed leads; it does not fabricate opens, deliveries or revenue. Note that consent evidence still needs independent Delivery policy review and recheck before any attempt.

Proposed controller actions for Cassian: `V2::Outreach::CampaignsController#index/show/create/update`, `LeadsController#index/show/create/update/record_consent/withdraw_consent/suppress`, `AccountsController#index/show/create/update`, `AnalyticsController#show`. Create campaign body is `{id,operation_id,name,status}`; create lead body is `{id,operation_id,email}` under a campaign path; create account body is `{id,operation_id,campaign_id,mailbox_id,label}`. Updates carry `operation_id` and `expected_version`; consent recording additionally requires source, observed_at and an explicit true attestation. List responses include `items` and nullable `next_cursor`; public records include version for optimistic editing. These are branch-source interfaces awaiting canonical contract reconciliation.

The consent continuation adds `app.campaign_consent_events` in migration 00009. Each lead update writes an append-only actor/status/source/time event in the same tenant transaction before its operation result is committed; runtime roles receive SELECT/INSERT but no UPDATE/DELETE on this history. Address edits record an unknown reset, explicit withdrawal records withdrawn, and the separate attestation records granted. Earlier events remain after a later status change. This is a persisted human record and does not itself satisfy Delivery's send policy.
