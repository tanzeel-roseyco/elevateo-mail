## Mac runner acceptance plan

Use an isolated, pinned macOS runner with Xcode command line tools, Rust universal targets and a reviewed Cargo.lock. Before invoking the script, provide an authorized Developer ID Application identity in its temporary keychain and Apple notarization inputs through the runner secret store. The script deliberately fails before build when any required item is absent. Record commit, lockfile hash, Xcode/Rust/Node/Tauri versions, exact command, DMG checksum, `lipo -info` for the app executable, `codesign --verify --deep --strict`, `stapler validate`, and Gatekeeper assessment. Copy no secrets into artifacts or logs.

On clean Intel and Apple Silicon Macs, mount, install, launch and quit the DMG, then verify CSP prevents remote navigation and local capability denies unexpected IPC. When the native auth contract lands, exercise one authorized login, wrong-state callback, replayed callback, expired callback, logout token clearing and prior-version upgrade; block release if any fails. The current native shell intentionally cannot pass the login case, so it remains an installable-shell candidate only. The release workflow must not publish or auto-update until root accepts these receipts.

## Root online-only decision reconciliation

The selected initial native model uses one exact configured HTTPS origin and the existing web cookie session. No custom PKCE, OS keyring, callback scheme or new server auth is admitted for this phase. The Mac overlay registers no callback. Orion owns the shared navigation/origin implementation; this branch merged Orion 5859593 lineage, which still contains pre-decision PKCE/keyring source, so a later exact Orion reconciliation is required before this branch can be called online-only. The static Mac validator must be updated against that settled common source, then queued with Soren. Current shared source does not satisfy the decision merely because the Mac overlay exists.

Read-only target-lane inventory: this workspace and fleet shell report Linux, with no `xcodebuild` or Windows PowerShell command found; no existing free macOS or Windows runner was identified in the accessible workspace. [Tauri's DMG guide](https://v2.tauri.app/distribute/dmg/) requires a Mac computer for DMG creation. [Tauri's Windows installer guide](https://v2.tauri.app/distribute/windows-installer/) permits Linux NSIS cross compilation with caveats, so an unsigned NSIS candidate might be possible in Soren's fleet Docker lane if the pinned compiler/NSIS toolchain is supplied; that would not prove Windows install or signing. No runner, signing identity or credentials were used.

Static validator continuation: the Mac candidate now rejects a remote Tauri capability, nonempty privileged permissions, and `dangerousRemoteDomainIpcAccess`, regardless of the exact website origin. This is a configuration guard, not proof that runtime navigation or cookie handling is safe. Soren should compile/run these static tests after Orion's online-only source lands.
