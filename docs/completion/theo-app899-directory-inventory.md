## Concrete missing functionality

1. **Verified person binding and actual accounts:** The roster cannot become an active staff directory until an authorized operator provides verified real Auth subject and organization membership mappings. Keep this a separate reviewed operator workflow; do not fabricate email/UUIDs, invite, or invoke the migrator in this task. The existing unbound roster remains visible and explicitly labelled.
2. **Picker-readable active member list:** Grant GET is owner/admin administration data and does not serve an ordinary mailbox reader's assignment picker. BE02 target validation checks current organization membership, but the frontend has no paginated safe list of current eligible Auth UUIDs. Thus a user must know/type a UUID; an unbound config key cannot be selected. This is the practical app gap even if V2 grants pass runtime.
3. **Runtime proof of read/write grants:** Source routes, DTOs and UI tests are present, but current integrated authenticated HTTP/PostgreSQL and real browser proof for owner/admin read, revisioned write, revocation, cross-org denial and no mailbox-content escalation is still required. Avoid treating older structural tests or mocked page tests as that proof.
