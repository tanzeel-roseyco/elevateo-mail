The SQL job row lock is the cancellation linearization point. With no first possible call, no attempt and no active lease it marks `cancelled` and clears the queue. For a leased or possibly attempted job it records `cancel_requested_at` and leaves the delivery state unchanged; the worker must recheck the flag under the same lock before admission and reconcile any possible outcome. Session and scoped draft access are checked before and after the lock. Idempotent replay uses one audit key. The API validates the redacted status fields, projects the canonical `CancellationResult`, and rejects unexpected provider data.

Tradeoff simulations for root (not executed): (1) cancellation wins the job lock before admission: terminal cancelled, zero attempts; (2) admission wins: cancellation request only, eventual accepted/rejected/unknown evidence controls outcome; (3) a lease exists but no attempt is durable: request remains pending until lease ownership resolves, conservatively avoiding false cancellation. A restored control epoch cannot itself prove provider non-delivery.
