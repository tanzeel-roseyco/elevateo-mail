# SEND-809 worker persistence candidate

Baseline `bbf2353b254a05d48c2da7a508c143e6fba78691`. Migration 00010 adds additive owner functions over the BE03 intent/jobs/attempts tables. The original approved snapshot and policy binding remain immutable; no new canonical API contract is claimed. `claim_job` locks the job row and returns a fencing generation. `authorize_attempt` uses a read-only private session freshness guard, policy revision, mailbox enabled state and epoch before recording the first possible submission time. An expired dispatch lease becomes `unknown` and schedules reconciliation; it never authorizes automatic replay. `record_observation` requires a valid fenced lease and records simulated local driver evidence. Unknown observations are capped at five before a durable needs-review hold. `cancel_job` is owner-internal pending Cassian's scoped API facade.

Exported SQL: `app_send_private.claim_job(uuid,uuid,uuid,integer)`, `authorize_attempt(uuid,uuid,bigint,uuid,uuid,bytea,text,integer)`, `record_observation(uuid,uuid,bigint,uuid,uuid,text,text,bytea)`, and owner-only `cancel_job(uuid,uuid,uuid)`. Nadia/Elara should treat `unknown` as unresolved, never sent; only an accepted observation yields accepted. Worker functions only have `elevateo_worker` EXECUTE, while tables retain owner-only RLS. The private session guard is needed because the BE02 write guard deliberately requires a request-local write transaction and cannot be reused by an offline worker.
