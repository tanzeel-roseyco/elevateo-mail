## Finding G1 — MEDIUM: key generation does not establish its private directory boundary

Location: keys.py:12–18. Unlike generate.py:21–24, keys() neither requires an absolute canonical root nor rejects a symlinked root. It also does not verify ownership or unsafe write permissions of root/config/dkim or their ancestors. O_EXCL rejects an existing final filename (including a final symlink), but follows directory symlinks; mode 0600 applies only to the new file.

Reproduction specification, NOT EXECUTED: in an isolated Linux Docker fixture create a valid generated tree A, create a directory symlink B pointing to A, and invoke keys(B). The function loads B/manifest.json and creates keys through B/config/dkim rather than rejecting the alias. A relative root is likewise accepted despite the CLI's ABSOLUTE_PRIVATE_ROOT contract. For the security consequence, make config/dkim writable by a second UID before invocation: that UID can rename or replace key paths, including substituting an attacker-known valid private key after generation. File mode 0600 does not prevent mutation of directory entries by another directory writer. Exploitability requires an unsafe operator-supplied tree or writable ancestor; this is not a claim that generate() normally creates such a tree.

Recommendation: enforce the documented canonical absolute private-root precondition in keys(), reject symlinked directory components and unsafe ownership/write permissions, and bind key creation to verified directory descriptors on Linux if hostile concurrent filesystem mutation is in scope. Merely resolving a path before open leaves a check/use race. Keep exclusive creation; do not replace it with overwrite or silent key rotation.

Suggested regressions in fleet Docker: canonical private generated root succeeds; relative root and symlinked root/config/dkim fail before key creation; second-UID writable destination fails; final key symlink/preexisting key remains unchanged. Verify no key output is written outside the accepted tree. Harden generate() against ancestor replacement too if untrusted writable parents are supported: its initial resolve check alone is not a race-proof guarantee.
