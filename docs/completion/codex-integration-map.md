## 3. Contracts and genuine gates

The canonical read contract is [C:contracts/v1/README.md](../../contracts/v1/README.md), with OpenAPI SHA-256 `94c5f31bc5d514fed420dcbcee2f6ce49bf4254e325000ea0794fe6a1140e8ca` and README SHA-256 `17d899805779a043d952be9fa8e894cc084ed758412b0c9c8d6ba01bab2bfc4e`, verified here. - Implement `GET /v1/session`, `/v1/mailboxes`, `/v1/mailboxes/{mailbox_id}/threads`, and `/v1/threads/{thread_id}` with required `mailbox_id` on detail. `/v1/session` does not log in a user. Login/bootstrap/logout/switch routes are not frozen yet.
- Preserve host-only HttpOnly `elevateo_session`, SameSite Strict, Secure under HTTPS; the explicit isolated Docker HTTP exception is the only Secure=false profile. Current session/membership is authority; context/version headers are consistency checks. Revoked identity returns 401 before stale context 409; inaccessible and missing objects share generic 404.
- Unsafe routes require exact Origin and unpredictable per-session CSRF, with a separately settled unauthenticated login bootstrap. No positive authorization cache, tokens in browser storage, client-selected principal, direct Auth/Storage browser access, or inherited constant CSRF marker.
- Keep same-origin relative `/v1`, no-store, redirect denial, a 10-second client deadline, bounded JSON streams, opaque context-bound expiring cursors and plaintext rendering. Existing limits are 50 mailbox/summary entries, 20 detail messages; response byte caps are 16 KiB / 128 KiB / 256 KiB / 2 MiB respectively, and 4 KiB for errors. Reads never mark messages read.
- Draft mutations retain JSON `expected_version` and HTTP 409 `draft_conflict`; older 412 proposals are superseded. Mutation identity, duplicate-payload rules, durable result lookup, retention/tombstones and authorization on lookup still need accepted design. Current draft version or `last_request_id` cannot identify an earlier lost response after a later save.
