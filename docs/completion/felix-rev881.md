## Confirmed defect

**MEDIUM — down migration leaves a migration-owned schema grant.** Migration 00018 grants `USAGE ON SCHEMA app_attachment_gateway` to `elevateo_attachment_gateway` in `up` line 81. Its `down` lines 87–91 drops the helper and revokes owner Auth execution but does **not** revoke that schema grant. Leonie's bootstrap creates/owns the schema and explicitly permits gateway USAGE only as a future exact ACL state; it does not issue that grant (bootstrap lines 34–48). After rolling migration 00018 down, the gateway retains access to the now-empty schema. This is a persistent privilege change outside the helper's lifetime, and a later function with permissive EXECUTE could become callable. **Fix:** `REVOKE USAGE ON SCHEMA app_attachment_gateway FROM elevateo_attachment_gateway` in `down` while preserving the bootstrap-owned schema; assert owner, exact ACL and function absence before/down/up in Soren's disposable role fixture. Root and Cassian received immediate `msg_71b875fd558d` and `msg_52a43957a379`. This is source-proven rollback drift; no runtime failure was observed by Felix.

## Other functional and security checks

The migration runs the one-time `authorize_session` owner grant under `elevateo_session_owner`, switches to `elevateo_owner`, and verifies the restricted LOGIN, existing attachment table, Auth function owner, dedicated schema owner/ACL and absence of other schema functions before creating one fixed-search-path SECURITY DEFINER helper. It checks session identity, digest/version format, context/generation, nested Auth result, organization membership, mailbox visibility/membership and exact clean attachment scope before returning private object metadata (migration 8–78). It revokes PUBLIC/API/read/worker function execution and grants the gateway only the helper. The bootstrap creates the schema with `elevateo_owner` ownership under `supabase_admin`, denies privileged role attributes and memberships, and refuses unexpected schema ACL entries (bootstrap 5–48). NOCREATEROLE migrator role membership/SET permission and actual PostgreSQL owner behavior remain external Soren gates; this review does not claim a successful migration.

The app regression request helper now merges explicit keyword overrides into the signed JSON body (test 62–68). Thus the expired claim and wrong mailbox cases actually exercise protocol/authority branches, rather than passing a keyword into the wrong Ruby parameter; the test asserts no Storage read and the expected authority-call count (87–99). The checksum fixture deliberately uses equal-length but different bytes and asserts both facts before expecting no released bytes (111–123), separating the SHA guard from size rejection. Positive release, forged signature, revocation during I/O and timeout are also represented in the test. The reviewed app handler fences capacity, verifies claim, checks byte length and digest, rechecks authority after Storage I/O, and denies release on changed binding/expiry (handler 18–42). The gateway remains private and narrow in this packet; actual Auth/Storage and direct-role denial tests were outside the read budget.
