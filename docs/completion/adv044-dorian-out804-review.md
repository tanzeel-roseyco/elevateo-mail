## Findings

1. **HIGH — private mailbox authorization is bypassed by the account policy.** Migration lines 70–71 establish a same-organization mailbox FK. Lines 96–102 then call an account `visible_mailbox` predicate that only verifies the same organization and mailbox ID exists; it does not require the current actor's `app.mailbox_memberships` record. An organization actor with a valid outreach digest can therefore select or link a private mailbox account outside their mailbox access. The mutation policy inherits account visibility for account resources. Require actor-specific mailbox membership and the intended capability in `USING` and `WITH CHECK`, and add a valid-digest cross-actor private mailbox denial case.
2. **HIGH — consent attestation accepts a forged actor.** `campaign_consent_events.actor_id` at migration line 45 is not tied to the authenticated actor. The generic RLS write policy at lines 117–119 checks organization/digest but not `actor_id`; API INSERT is granted at line 124. A valid-digest organization actor can record a granted manual attestation under another UUID. Bind the actor at the database boundary, or permit insertion only through a restricted function that derives the actor from the session, and test a forged actor ID.
3. **MEDIUM — mutation idempotency history can name a nonexistent resource.** Migration lines 80–89 allow `campaign_mutations` resource kinds without a corresponding resource FK or existence check; line 124 grants API INSERT. A valid-digest organization actor can reserve an operation key for a phantom campaign or lead, poisoning later idempotent work. Move reservation and result recording into a restricted resource-bound transaction or validate resource existence and ownership at insert, then test a phantom resource ID.
4. **HIGH — rollback deletes durable consent and suppression history.** Migration lines 127–129 unconditionally drop all six tables, including consent events, suppressions, and mutation history. A rollback after writes destroys the audit and suppression records needed to reason about later sends. Make `down` refuse nonempty durable tables unless a separately authorized destructive recovery path is used; cover populated rollback.

These are source findings and proposed tests; none were run in this review.
