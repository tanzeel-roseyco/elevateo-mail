## Findings

1. **HIGH — manual attestation is presented as granted consent without a provenance qualifier in compact responses.** `LeadsController#record_consent` at lines 87–100 checks only caller-supplied `attested: true`, `source`, and `observed_at`, then writes `consent_status: "granted"`. The compact lead projection in `base_controller.rb` line 53 includes `consent_status` but omits `consent_evidence_kind`; the latter appears only in detail at lines 60–64. Test lines 73–86 expect `granted` from a manual attestation. This does **not** prove that a live send is possible, because send admission was outside review, but it makes unverified manual provenance look like a positive consent state to list consumers. Keep a distinct manual-unverified state/label in every relevant response, or prove and test that all deliverability/send admission paths refuse this state; do not present it as permission to send.
2. **MEDIUM — rejected-attestation test has an incorrect mutation oracle.** Controller line 87 rejects `attested != true` before constructing the repository. Test lines 123–129 correctly expect HTTP 400 and no consent event, but line 127 asserts that *some* SQL contains `SET version=version+1`. That is not evidence that the rejected consent operation was mutation-free and conflicts with the intended early rejection. Assert no `UPDATE app.campaign_leads`, no consent event, and no campaign mutation ledger row instead. If another authentication query happens to contain the version fragment, the current assertion can pass for the wrong reason.
3. **MEDIUM verification gap, not counted as a confirmed defect — withdrawal occurrence timestamp.** Controller lines 114–121 clear current attestation fields and ask the repository to append history. The reviewed repository lines 185–193 insert a withdrawal event with `observed_at: nil`; the test lines 111–120 only check that an INSERT string exists. The event table may supply a server `created_at` default, which was outside this bounded review. Verify a persisted server occurrence timestamp and actor/tenant scope in the database test; retain the prior grant evidence in history while current fields clear.
