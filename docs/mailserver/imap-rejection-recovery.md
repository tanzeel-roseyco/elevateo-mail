# Durable IMAP rejection recovery

A deterministic MIME rejection now records account, credential version, UID validity, UID, SHA256 and one of five bounded reasons, then advances the cursor in the same transaction. The worker continues with later messages. Parser errors only use this path: transient storage/network errors are retried.

The worker SQL function validates the current lease token, account version and cursor. Account-row locking serializes accepted and rejected writes. Replays require identical bindings; accepted/rejected conflicts fail with SQLSTATE23514. Forced RLS and grants keep metadata out of the API role. The downgrade takes an exclusive lock and refuses nonempty receipts (55000).

No malformed raw body is persisted in the rejection table. Oversize whole-page validation still holds the page before parsing; this is not a universal dead-letter facility. Attachment/scanner runtime wiring and production provisioning remain separate work.
