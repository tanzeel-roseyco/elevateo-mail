# Held private attachment scanner

Run `bundle exec ruby bin/attachment-scanner --once` or `--run` in the private test profile. It requires worker DB role, outbound hold, `ELEVATEO_SCAN_PROFILE=private-storage-test-v1`, and both `ELEVATEO_SCAN_STORAGE_TOKEN_PATH` and `ELEVATEO_SCAN_STORAGE_BUCKET`. The token is read once through the existing private-file boundary. Do not use live credentials; public endpoints and production supervision are not implemented by this change.

One claim per iteration bounds memory and in-flight work. A single DB connection has5s connection/checkout,3s statement and1s lock limits; network scans run outside a DB transaction. TERM/INT sets a stop flag; in-flight I/O finishes or hits its own deadline before exit. Storage allows5s metadata and20s object aggregate deadlines with Net::HTTP retries disabled and strict EOF handling. Errors are redacted. Clean and malware verdicts are durable; missing objects remain held and follow existing retry fencing.

The fleet fixture launches the actual executable and verifies clean/EICAR results, missing-object retries, invalid args/profile/token/role, idle TERM/INT and exactly one claim. Slow-trickle and truncated-response transport tests cover deadline and framing failure. The runner caps subprocess time/output/event count and escalates termination without leaking subprocess exception bodies.
