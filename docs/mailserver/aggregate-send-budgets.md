## Reservation and authority

Only the held Mox profile uses these tables; no production profile is enabled. An administrator must provision an enabled mailbox route and every required limit. Routes associate organization/mailbox with personal, outreach or seed group and a shared egress pool UUID. Organization/group/mailbox limits use tenant-scoped keys; sender domain, destination domain and egress pool limits are global. Limits are recipients per UTC day, not bytes, concurrent connections, account counts or proved IP quotas. No guessed live ceilings are enabled. The712 account reservations and500/200 daily planning projections remain distinct.

An immutable canonical snapshot determines recipient counts; duplicates and more than100 recipients fail validation. One authorization transaction takes deterministic locks, inserts the attempt, reserves every axis, stores versions and refreshes time/lease authority. Missing configuration, disabled limits, exhaustion or expiration roll back all charges and the attempt. Exhaustion holds until at least next UTC day and15 minutes; configuration failures back off15 minutes; expired admission retries after15 seconds. Final authorization requires the same route/limit versions, UTC day and single reservation timestamp. Versions change under lock; final authorization winning a race cannot retract SMTP bytes already authorized.

Unknown acknowledgments retain capacity and reconcile; they do not resend or refund. Private receipts and imported inbox content remain subject to existing tenant authorization. Tables are forced-RLS and unavailable to runtime roles outside definer functions. Migration rollback locks attempts before budget tables and refuses nonempty history/configuration; operators must use a reviewed forward correction for populated installations.
