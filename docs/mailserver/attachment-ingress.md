# Private Mox attachment ingress

The held mox-imap-test-v1 worker accepts optional ELEVATEO_INBOUND_STORAGE_TOKEN_PATH and ELEVATEO_INBOUND_STORAGE_BUCKET. Configure both or neither. The token must be a regular single-link file, mode0600, owned by root or the worker UID, opened without following symlinks and read once with a4096-byte limit. The endpoint remains the internal http://storage:5000 service. This is not public deployment configuration.

The shipped inbound process parses MIME, writes private objects and commits attachment records under its IMAP lease. Existing receipt identity is checked before a new insert, so replay after cursor recovery retains thread/message/attachment IDs and restores last_uid monotonically. Invalid identity, expired lease, credential revocation and rejection conflicts remain denied. Migration27 down restores the previous function bodies; the roundtrip checks IDs, owner and grants. Storage duplicate HTTP400/409 succeeds only after an authenticated private GET matches exact bytes; no overwrite is enabled. Supabase documents duplicate-upload HTTP400 at https://supabase.com/docs/guides/storage/uploads/standard-uploads. The real Mox fixture then proves pending content is held, explicit ClamAV scans mark clean or malware, clean bytes round-trip exactly, malware stays inaccessible, and replay after cursor reset does not duplicate attachment records. Revocation and foreign/unauthenticated access deny download; a drifted public bucket fails closed and is restored in ensure.

This step wires inbound ingestion to private Storage. The fixture directly invokes ScanService; an independent background scanner and its runtime supervision are still separate work. No external mail or credentials are required for this private evidence.
