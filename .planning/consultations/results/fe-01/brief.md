## Proposed contract to settle before dependent code

The current repository's reliability document is a design specification. At this planning baseline it does not supply complete machine-readable DTOs or implemented endpoints. Existing source `MailroomGateway` and HTTP schemas belong to an older application and cannot serve as the new contract unchanged. Consultation should accept or amend the following concrete proposals, then the coordinator freezes their schema revision/hash. This does not require all backend endpoints to have been implemented first.

| Boundary | Proposed UI requirement / default | Decision or backend gap to resolve |
| --- | --- | --- |
| Session and context | Same-origin Rails session facade; gateway obtains the current actor, organization, visible mailbox capabilities and explicit local simulation mode. UI never stores a service credential or treats a route/header/role flag as authorization. | Freeze login/logout/current-session routes, cookie/CSRF/origin policy, organization selection, revocation response and current capability DTO with BE-02. Old `x-elevateo-csrf: 1` is only a marker, not a secret token. |
| Inbox and reader | Existing proposed `GET /v1/mailboxes`, `GET /v1/mailboxes/:id/threads`, `GET /v1/threads/:id`; bounded summaries separate from bounded message details; opaque cursors scoped to organization, mailbox, sort and filters; safe plaintext bodies. | Freeze summary/detail schemas, message pagination, nullable sender/subject fields, stable ordering and cursor invalidation. Missing/inaccessible objects follow the accepted non-enumerating server error policy. |
| Drafts | Existing proposed create and patch routes; server-generated draft ID and integer revision, explicit mailbox, recipients, subject, plaintext body and attachment references. Saving requires the prior revision. Proposal: canonical JSON `expected_version` and stable `draft_conflict` error with HTTP 409. | Settle this choice against the existing 409/412 alternative; define draft read/list recovery routes, allowed field sizes/recipient counts, reply references, attachment ownership and authoritative saved response. Legacy source limits are not automatically accepted. |
| Exact approval and send | Existing proposed `POST /v1/drafts/:id/send`, job status and cancellation routes. Human reviews the exact server-authorized sender, all recipients, subject/body and attachment identities at one saved revision. Submission binds `draft_id`, `expected_version` and a stable `client_request_id`; 202 means durable queued intent. | Freeze the full review envelope and whether fetching it uses the draft read contract or a separate endpoint. Define lookup/reconciliation after a lost submission response, including when no job ID was received. The UI must not invent a new send request to resolve uncertainty. |
| Send status | Preserve `queued`, `cancelled`, `dispatching`, `accepted`, `unknown`, `rejected`, `needs_review`; provider delivery facts are separate. Cancel is only available when the server says cancellation remains possible. | Freeze job DTO, polling/backoff/expiry and conflict behavior. `accepted` is not delivered; `unknown` never offers blind resend. Single-use approval and duplicate consumption remain backend invariants. |
| Collaboration and search | URL-visible mailbox/filter/search/selected-thread state; distinguish personal read state from shared status and assignment. Assignment/note/read changes go through gateway commands and current permissions. | These mutation/search routes and DTOs are not specified fully. Freeze a minimal supported set with BE-02 before implementing its actions; omit unavailable controls from the real mode rather than pretending a local state change is durable. |
| Attachments and settings | Display server-owned attachment status; only authenticated server download of a permitted, released attachment. Current account/mailbox settings use the session/capability contract; appearance is local presentation. | BE-05 must define upload/quarantine/scanning/rejection/download states and limits. No direct Storage URL or client credential. Defer unsupported settings mutations with explicit recorded scope. |

`src/domain` stays pure: validation/presentation state transitions have no React, stores, HTTP or credentials. All backend-owned behavior crosses a new `MailroomGateway` port. Define typed commands/results and runtime-validated wire schemas from the accepted contract, not a copy of old campaign methods. Prefer the smallest existing React state arrangement; do not introduce a query framework or global state library without a demonstrated need and dependency justification. URL state is not duplicated as an independent source of navigation truth.

Keep transport timeout/AbortController, same-origin credentials, no-store handling, bounded streamed parsing, validated success/errors and request-generation safeguards from the inspected source. Set endpoint-specific response bounds with the contract; do not blindly impose the old 262,144-byte bound on all thread content. Cache and in-flight identity must include actor, organization, mailbox and relevant filters. Abort/invalidate on account switch, logout or revoked access, and reject late responses from an old context. Never infer authorization from a cached capability.

Draft edits have honest unsaved/saving/saved/conflict/error states. Preserve the user's unsaved buffer when a version conflict occurs; reload or compare against the authoritative draft through an explicit recovery flow. A failed save must not silently overwrite a newer draft, advance the displayed saved revision, or enable approval of unsaved content. Warn on navigation with unsaved changes. Successful server saves survive a reload; browser-only form state is not durable persistence. No offline mailbox replica is added in this task.

For uncertain writes, reconcile the original request identity and authoritative resource; do not retry with a new identity merely because a timeout, network error or 5xx occurred. Editing after review invalidates that review. UI disabling prevents accidental clicks but does not replace server uniqueness, current authorization or immutable approval enforcement.
