# Analytical tradeoff scenarios

These are design walkthroughs, not executed application tests. No Obsidian connection was available in the observed tool/resource catalog, so no Obsidian simulation or capture is claimed. The requested connection-based validation remains missing. Later implementation tasks must run the concrete failure cases against real services and record actual outcomes.

| Scenario | Sequence | Weak design outcome | Accepted design and required test |
| --- | --- | --- | --- |
| Late accepted response | Worker A owns generation 1, provider accepts; A stalls. Lease expires; worker B owns generation 2 and records unknown. A receives the accepted response. | Rejecting every stale-worker write discards the only acceptance evidence. Repeating send may duplicate. | Store validated, attempt-correlated observation append-only; current reconciler makes fenced monotonic accepted transition. Stale A cannot overwrite projection. Test delayed return after lease transfer. |
| Two draft versions | Version 5 is approved. An old client later submits version 4, or a consumed draft is edited to version 6 and approved. | A unique `(draft_id, approved_version)` admits a second version and a second send intent. | Status/version compare-and-swap plus consumed draft intent prevents both. Retry same job; deliberate resend clones a new draft. Test concurrent and sequential requests. |
| Restored pending job | Provider accepted a send; app backup predates that fact. Restore backup after the provider idempotency window expires. | Database-only hold restores as enabled; deterministic key no longer prevents a new provider side effect. | External/default-held dispatch gate stays held; durable provider ledger survives app restore; reconcile before release. Test independent simulator ledger and expiry. |
| Database pool leakage | A transaction sets user A context and fails. Same connection then serves user B with no valid context. | Session-level claims or missing reset accidentally authorize as A. | Transaction-local validated context plus fail-closed policy; one-connection test across commit/rollback/errors. |
| Auth email escape | Developer tests invitation or password recovery with a real SMTP fallback still configured. | App's outbound campaign toggle is off but Auth still sends external mail. | Capture-only local Mailpit/disabled mail, explicit runtime SMTP allowlist and no provider egress. Exercise every Auth message path. |
| Bridge exposure | Email content contains a link/script/protocol message resembling a native command. | Generic secureStore/shell bridge reveals secrets or gains authority. | Text-only message rendering plus a minimal origin-bound command allowlist; raw secrets stay host-internal. Test untrusted-origin denial. |
| Unknown session creation | Coordinator times out after requesting a Devin task, before receiving the ID. | Blind retry creates two writers and doubles spend. | Search/reconcile task tag and existing sessions before create; stop dependent work if identity is unresolved. Record actual supported operations. |

Rails plus one PostgreSQL ledger has greater initial setup work than an in-memory demo, but it gives the required transaction, RLS, restart and restore semantics in the same authority. Adding a second backend or queue introduces cross-system consistency without a current requirement. The first foundation task therefore builds only the necessary real services and permission boundary, leaving messaging tables and provider behavior to their named tasks.

Two native desktop host languages add bridge conformance work. The accepted scope retains both because the user requested those roles; shared React UI and protocol fixtures contain that cost. A cross-platform Tauri host remains a documented alternative, not an unapproved replacement. Platform measurements should reveal whether a later change is warranted.

The three-opinion gate and complete small-slice code review have real execution cost. Cost controls, concise bounded task packets, one writer and two-attempt repair escalation reduce waste while preserving the user's required gates. Removing opinions or sampling code instead of reviewing all changed areas is not an accepted optimization.
