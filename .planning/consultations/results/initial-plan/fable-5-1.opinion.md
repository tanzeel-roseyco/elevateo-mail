**PLAN-ARCH: support with two prerequisite changes.**

- Change one, append-only provider evidence. Failure sequence: worker A leases job at generation 1, records the dispatch boundary, calls the provider, then pauses. Its lease expires. Worker B claims at generation 2, calls with the same key, times out and records unknown. Worker A resumes with the provider's acceptance and ID. Under `docs/contracts-and-reliability.md` step 5, the generation check rejects A's write, so the only true acceptance evidence is discarded and the job stays unknown. Fix: fence only the job state transition. Provider responses go into an append-only attempts table regardless of generation, and reconciliation reads them. Regression check, not run: two fake workers, forced lease expiry, stale worker returns accepted last, assert job reaches accepted without a third provider call.
- Change two, draft consumption. Uniqueness on approved_version does not stop a stale client approving version 4 after another user approved version 5. Both are valid distinct identities, so two mails leave. Require the draft to move to a consumed state on approval, and reject approval of any version of a consumed draft unless a new draft is explicitly cloned. Affected route: `POST /v1/drafts/:id/send`.
- Pooled claims: Supabase pooling in transaction mode makes session-level settings leak between requests. Require that every application query runs inside a transaction that sets claims with the transaction-local flag, and that policies fail closed when the setting is absent. Regression check, not run: pool size one, user A then user B sequentially, B must see nothing of A.
- Stale sessions: `.planning/POLYGLOT_ARCHITECTURE.md` section 5 already notes that a JWT may outlive sign-out. Make the per-request session-state check a hard dependency of BE-02, not an optional improvement.
- Rails versus Node: the maintenance risk is not Rails. It is the PHP SDK and Go doctor adding CI surface before the core exists. Defer TOOL-01 until after OPS-01 measurements. Smallest vertical slice: one organization, one mailbox, simulated inbound, draft, approval, simulated send, webhook acceptance, audit row, with API restart mid-flow. Measure RSS per process, p95 interactive latency and queue age at ten synthetic users.
- Strongest objection: the fenced-update rule exists to prevent a stale worker clobbering state, and my change weakens it. Simpler alternative: keep the rule and rely on reconciliation by tag. Tradeoff: reconciliation depends on provider list endpoints and retention, which the packet already identifies as external constraints.

If production Auth SMTP points at Resend during setup, inviting staff is a live send. Require Auth SMTP to be unset or loopback until the explicit send decision. Instantly connection also hands a third party send authority over the mailbox, so stage B is not side-effect-free even with warmup off. Recommend deferring stage B entirely until stage C is approved.

Sending identity is per verified domain, not per address, so the stable provider identity is domain plus from-address. Test fixtures: one alias that resolves to a shared inbox, one private inbox, and a two-domain split.

Strongest objection: deferring stage B delays learning whether the connection flow suppresses tests. Simpler alternative: run stage B on one disposable account on a reserved domain.
